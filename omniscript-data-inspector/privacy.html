Privacy policy — OmniScript Data Inspector

Last updated: 31 October 2026

The short version

This extension collects nothing and sends nothing anywhere. What it stores in your browser is the order of the panel's tabs once you change it, flags that the short tours were seen, the Mask values at start flag if you tick it, and, while Remember my settings is on (it is on by default), your panel settings and the views you last chose (never any data), all in the browser's extension storage on this computer. Everything else it holds is kept in memory and is gone when DevTools closes.

It requests one permission, storage, for the entries above, and no access to any website. It has no background service worker, no content scripts, and makes no network requests of its own. It never changes the OmniScript or its data.

What it reads, and when

The extension only does anything while you have DevTools open (in Chrome, Edge and other Chromium browsers, or in Firefox) and the OmniScript panel in view.

Page data. It reads properties of elements on the page you are inspecting, using the browser's standard DevTools API (devtools.inspectedWindow) — the same access the DevTools Console already gives you. By default it looks for three properties an OmniScript element exposes: jsonDataStr (the live data payload), jsonDef (the element/structure definition) and scriptHeaderDef (script header, including the custom-label map used to resolve labels in multi-language scripts). You can point the Data property and Definition property fields at any other property name, in which case it reads that instead. To find those elements it walks the document, any open shadow roots, and same-origin iframes.

Network traffic. The Calls tab observes requests the inspected page makes, using the DevTools network API (devtools.network). For requests that look like OmniStudio calls (Data Mappers, Integration Procedures and Remote Actions) it reads the request and response bodies in order to decode the call, its input and its output. This is the same traffic already visible to you in the Network tab.

Open in Designer. To offer a link to the OmniStudio Builder or OmniScript Designer, it reads the host elements' tag names, classes and their data-omni-id / omniscript-id attributes, and the page's origin and path (the path only to tell a managed package from core OmniStudio; it is kept in memory and never stored). The choice of designer can be forced in Settings. The link is built in the panel and opened in a new tab only when you click it; nothing is sent. Open record in the Data tab uses the same page origin to build a link to a record whose Id appears in the data, and opens it the same way.

Frames. It asks DevTools which documents are loaded, so it can find an OmniScript inside an iframe such as the OmniScript Designer preview. Firefox reads the top document only.

Files and clipboard. It reads no file from your computer and never reads the clipboard.

What it writes to the page. While scanning it sets window.__omniHosts on the inspected page to an array of the elements it found, and window.__omniPeekCache to the parsed copy of the definition it last read, so it does not have to parse it again on every refresh. To avoid copying a large payload over and over, each read of the data property also returns a short hash of the value (FNV-1a, computed on the page) and, when the hash matches what the panel already holds, the page answers "unchanged" instead of sending the text again. The hash is not stored anywhere and the Refresh button always reads the whole value. When you click Inspect element it also sets window.$omni to the selected element and calls the DevTools inspect() helper, so you can poke at it in the Console. When you use Highlight on page (or turn on Highlight on hover) it scrolls the matching element into view and draws a temporary outline over it: a single div with the id __omni_inspector_outline that removes itself after a couple of seconds.

What it sends. Nothing. The panel makes no requests of its own, to your org or anywhere else.

All of this stays in the DevTools panel in your browser. It is never transmitted. It is held in memory only. The panel keeps, in memory, the last 12 reads of the data (up to about 4 MB) and the calls it captured. None of it is discarded the moment the page navigates or the OmniScript closes: the last data read deliberately stays on screen, marked as stale, so you can still look at it after a script ends or the page reloads. It is replaced when you select another OmniScript or change the Data property field, and everything is discarded when you close DevTools.

What is stored in your browser

Four things, all in the browser's extension storage (storage.local), on this computer only (it is not synced):

  • The order of the panel's tabs, once you change it (removed again when you put the default order back).
  • Four flags that you have seen the short tours (the panel's and one per tab), written when you close them, so they do not show again (Show the tour again in the help, or Show tours again in Settings, clears them).
  • While Remember my settings is on (in Settings, on by default): the panel's settings (its switches, text size, refresh rate, time format, the designer choice and its namespace) and the views you last chose, preferences only. The filters that hide rows (Failed only, Visible only) and the property names (Data property, Definition property) start fresh in every session. Unticking it deletes all of it, and only that choice is kept. Data, filter text, captured calls, the history of reads and the Mask values switch are never kept.
  • Mask values at start (in Settings, off by default): one yes-or-no flag, kept whether or not Remember my settings is on, that turns the Mask values switch on when DevTools opens. Unticking it deletes it; the switch itself is never stored.

The extension does not use localStorage, sessionStorage, IndexedDB or cookies. With Remember my settings off, your panel settings are held in memory and last until DevTools is closed. The Restore default settings button in Settings, and the Reset next to a single setting there, put settings back without reloading DevTools.

The Calls list is held in memory too. Unless Clear on reload is ticked (it is off by default) the captured calls are kept across page reloads. They are cleared when you close DevTools, when you reload with Clear on reload ticked, or when you press Clear list.

What leaves your machine

Nothing, unless you ask for it.

Save file (in Data, under Export) and Export (in Calls) write data to your own disk when you press them, and the Copy buttons, including Copy JSON, Copy input and Copy report, the right-click menu and the copy keyboard shortcut put what you chose on your clipboard. Nothing is uploaded. The Mask values switch (off by default) replaces strings and numbers with placeholders in everything saved, exported or copied, but not in what is shown on screen.

In the help, More on the website and Full guide open a page of this website (the reference and the task guides) in a new tab only if you click them; the panel passes nothing to the site beyond the page's address.

The toolbar popup, the help panel and the panel's status bar offer a Buy me a coffee link to buycoffee.to, which opens in a new tab only if you click it. That site is operated by someone else and has its own privacy policy. No information about you is passed to it by this extension.

Analytics and third parties

There are none. No analytics, no telemetry, no crash reporting, no advertising, no cookies, no user accounts, no third-party services of any kind. No data is sold or shared, because none is collected.

Data you retrieve from your org is your responsibility

This extension is a viewer. It shows you data that is already on the page you are inspecting and that your Salesforce user is already authorised to see. What that data contains, and what happens to it once you look at it, is outside the extension's control and squarely within yours.

Be aware that an OmniScript's data JSON or a captured call can carry personal data, customer records, and internal identifiers. Request payloads may also carry session tokens.

So, concretely:

  • Where you point it matters. Prefer a scratch org, a sandbox, or test records when you are exploring or capturing screenshots. Anything you capture from a production org is production data.
  • Exports and copies are ordinary data. Pressing "Save file" or "Export" writes org data to your disk, and copying puts it on your clipboard, where other applications and clipboard managers can read it. Neither has any protection unless you turned on Mask values first. Where it then goes — a ticket, a chat message, a shared drive, a colleague's laptop — is entirely your decision.
  • Screenshots and screen shares count too. The panel is designed to make data legible, which also makes it legible to whoever is watching your screen.
  • Your own obligations still apply. Your organisation's policies, any confidentiality agreements it is under, and data protection law such as the GDPR govern this data regardless of which tool you viewed it through. Using this extension does not change what you are permitted to do with what you see.

The author provides this tool as-is and accepts no responsibility for how data retrieved through it is handled, stored, or disclosed. This is a plain description of how the tool works, not legal advice — if you handle regulated or confidential data, follow your organisation's guidance.
