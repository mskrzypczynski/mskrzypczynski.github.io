OmniScript Data Inspector

Live OmniScript data, structure and the calls it makes, in a DevTools panel for Chrome, Edge and Firefox.

Debugging an OmniScript is not a friendly experience. The data is in there somewhere, the calls happen out of sight, and a Data Mapper can fail while the response comes back as a cheerful HTTP 200. This adds a DevTools tab that just shows it.

What it does

  • Data — the live data as a collapsible tree, a form (each key under the label of the element that owns it) or Raw text, re-read about once a second and quiet while nothing changes. A value that changes flashes amber, and a collapsed branch that holds a change is marked with a dot. The filter box takes words, an OmniScript path such as Step:Rows|2:Field, or key=value, and branches still open and close while you search. Right-click a row to open the record behind an Id, or to copy the value, the path or the %merge% field. Copy JSON and Save file keep the page's exact text; line numbers in the tree match the Raw view; the open branches stay pinned at the top while you scroll. Untick Auto-refresh for a true manual mode.
  • Structure — every element the script is built from, joined to the live data. Selecting one opens a column of cards, the same frame for every fact: Current value first on every element (a step shows its values as a Form, a Tree or Raw text), then Formula, Set Values, Options, Visibility and Validation, each with its verdict in the header and a Copy. A show rule reads as a table of its conditions (met or not, must be, is now) with a plain-words verdict such as Hidden: Plan is "Standard", not "Premium". A Valid column at the end of every row says at a glance what would stop Next now (✗), what passes (✓, on a step) and what the panel cannot tell (–), and the current step's Validation tab lists what may stop Next: required fields still empty in every row of a repeat block, validations and Set Errors that fire now, and custom components. A Properties tab explains each setting of an element; the Calls tab shows what an action sends and where the answer lands; with nothing selected the pane summarises the script. A hidden element shows a closed eye, a conditional one a small diamond; the marks sit in their own column, whose header opens a legend of every mark. Follow current step keeps the current step selected as the script moves on, and edits made in the Designer are picked up by themselves. Formulas are worked out as estimates, marked ≈, and never counted as a failure.
  • Calls — every Data Mapper, Integration Procedure and Remote Action call the page makes, named by key, batched calls split apart, and a verdict that does not trust HTTP 200 (Succeeded or Failed, with no response, an expired session and an Aura system error told apart), with the failure text at the top of the detail. A chainable procedure that ran as several calls is one row, chain · N calls, with each call under it, and repeated calls are tagged. Filter with words, Failed only, or in:, url:, step: and repeat:. Open a call for its Input, Output and Options, Copy input, or Show raw for the request exactly as the page sent it and the answer as it came back. The tab badge turns red as soon as a call fails, the list is kept across reloads, and Export saves the calls to JSON.
  • Linked together — jump from a value in Data to its element in Structure and back, from an action to its calls, and from a call to the element that made it. Open in Designer opens the selected script in the OmniStudio Builder or the OmniScript Designer, deciding between core and a managed package from the host element, the definition, the page address and the calls seen; Settings can force either. Inspect element selects the host element in the Elements tab and leaves it as $omni in the Console.
  • Mask values — a switch (off by default) that replaces strings and numbers with placeholders in everything you copy, save or export. Tick Mask values at start in Settings to have it on whenever DevTools opens. Copy report puts a few lines of Markdown for a ticket on the clipboard.
  • Settings — the gear before ? opens them: Text size, Mask values at start, Remember my settings (on by default: your settings and the views you last chose are kept in the browser's extension storage on your computer, never any data), the Refresh rate of the Data tab (Fast, Normal or Gentle), the Calls options, Open in Designer, every setting that differs from its default with a Reset, and Restore default settings. Hide the list with Ctrl+\ to give the detail the whole width.
  • Easy to step into — each tab is one list or tree, one filter box and a few buttons; the deeper tools sit in a menu, a detail tab, a filter prefix or the right-click menu. A short tour the first time, a searchable ? help with a Start here list per tab, right-click any control for its help entry, and the reference and guides on this site, generated from the same help. Light and dark, from 340 px up, keyboard and screen-reader friendly.

Replay, which records the steps you keep repeating and replays them, is an extension of its own: OmniScript Replay.

Install

Chrome Web Store · source on GitHub (GPL-3.0), which also builds the Firefox package

Privacy

Only the storage permission, for the order of the tabs, the flags that the short tours were seen, the Mask values at start flag and, while Remember my settings is on, your settings and the views you last chose; no host access. Nothing is sent anywhere, and the OmniScript and its data are never changed. Read the full privacy policy, or the source — it is all there is.
