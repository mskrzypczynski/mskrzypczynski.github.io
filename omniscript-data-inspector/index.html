OmniScript Data Inspector

Live OmniScript data, structure and remote action calls, in a Chrome DevTools panel.

Debugging an OmniScript is not a friendly experience. The data is in there somewhere, the remote actions happen out of sight, and a Data Mapper can fail while the response comes back as a cheerful HTTP 200. This adds a DevTools tab that just shows it.

What it does

  • Data — the live payload as a collapsible tree or pretty-printed Raw text, re-read about once a second (less often while nothing changes) and highlighting what changed as you click through the script. Changed values stay marked, with Prev / Next to jump between them and a hover showing the previous value. Filter keys and values (branches still expand and collapse while filtering), keep values you care about in a watch list, and compare any two of the last 20 payloads. Line numbers in the tree match the Raw view. Untick Auto-refresh for true manual mode: nothing is re-read until you press Refresh. Point Data property (under Advanced, and shown automatically whenever it is not the default) at any property you like.
  • Structure — every element the script is built from, joined to the live data: current value, required and conditional markers, and visibility rules as readable expressions. Hidden elements are dimmed and the detail pane says which rule fails and what the field holds right now. It also shows Set Values assignments, Set Errors and validation messages, and in multi-language scripts the resolved custom labels, with a warning when a key is missing. Follow step (on by default) keeps the current step selected as the script moves on. The Definition property can be changed too; like Data property it is under Advanced and shown automatically whenever it is not the default.
  • Remote actions — every Apex call the page makes, with Data Mappers and Integration Procedures named by bundle or key, batched calls split apart, and errors flagged even inside a successful response. Show input, output and options per call, diff a call against the previous one to the same place, filter to errors or slow calls, and expand long error messages with Show more. Calls are kept across page reloads unless you untick Preserve on reload. OmniStudio only is always visible, and when filters hide calls the list says how many (“N calls hidden”) and offers Show all.
  • Linked together — jump from a value in Data to its element in Structure and back, see the calls an element makes, and use Inspect element (under Advanced) to select the host element in the Elements tab and leave it as $omni in the Console. Child scripts (under Advanced) also lists scripts nested inside another one.
  • Mask values — a switch (off by default) that replaces strings and numbers with placeholders in everything you copy, save or export, so a payload is safer to paste into a ticket. It always starts off.
  • Scope bar — the OmniScript picker lists each script once, by its Type/SubType/Language, and applies to every tab.
  • Settings for the session — the Advanced switch, Data view, property names and the other switches and the Slower than value last until DevTools is closed; nothing is stored apart from the tab order. Restore default settings in the help panel puts every setting back to its default without reloading DevTools (the Advanced switch stays as it is); the same place lists each setting that differs (with a Reset for each), and a Custom settings button appears in the scope bar while any do.
  • Keyboard and screen readers — the element tree and call list move with the arrow keys or j/k, tabs switch with the arrow keys or 1 2 3 and can be dragged into any order (or moved with Alt+Shift+arrows), which is kept, / focuses the filter, and ? shows the help with every shortcut. Controls report their state to screen readers.
  • Guidance — empty states that list what to try (including Reload page to capture from the start), and tooltips that name the shortcut keys.

Replay, which recorded the steps you keep repeating and replayed them, is now an extension of its own: OmniScript Replay.

Install

Chrome Web Store · source on GitHub (GPL-3.0)

Privacy

Only the storage permission, for the order of the tabs; no host access. Nothing is sent anywhere, and the OmniScript and its data are never changed. Read the full privacy policy, or the source — it is all there is.
