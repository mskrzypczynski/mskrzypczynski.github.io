OmniScript Data Inspector

Live OmniScript data, structure and the calls it makes, in a Chrome DevTools panel.

Debugging an OmniScript is not a friendly experience. The data is in there somewhere, the calls happen out of sight, and a Data Mapper can fail while the response comes back as a cheerful HTTP 200. This adds a DevTools tab that just shows it.

What it does

  • Data — the live data as a collapsible tree, a form (each key under the label of the element that owns it) or Raw text, re-read about once a second and quiet while nothing changes. Tick Track changes and changed values stay marked, with Prev / Next, a change log and Compare data: any two of the last reads, a JSON file from your computer, or the data since this step began, with repeat-block rows lined up by Id or Name so a deleted row is one change, shown side by side: Before and After in two panes with the rows lined up, changed values amber, added green, removed red, unchanged branches folded, and Previous / Next to walk the differences. The filter box takes words, an OmniScript path such as Step:Rows|2:Field, key=value, or a $ path query such as $..Code. Keep values in a watch list with a bell that tells you when one changes, or watch an expression such as Step:Total > 100. Sizes ranks what takes up the data as a list or a treemap you can zoom into, and Unused lists the keys no element of the script reads. Right-click a row for Where is this set? (the last change, the call that was running, the Set Values that write it), to open the record behind an Id, or to copy the value, the path or the %merge% field. Copy JSON and Save file keep the page's exact text; line numbers in the tree match the Raw view; the open branches stay pinned at the top while you scroll.
  • Structure — every element the script is built from, joined to the live data. Selecting one opens a column of cards, the same frame for every fact: Current value first on every element (a step shows its values as a Form, a Tree or Raw text), then Formula, Set Values, Options, Visibility and Validation, each with its verdict in the header and a Copy. Show rules read as one aligned table (ALL of / ANY of, must be, is now) with a plain-words verdict such as Hidden: Plan is "Standard", not "Premium". Type another value into the Is now cell to see what would change, without touching the page. The current step's Validation tab lists what may stop Next: required fields still empty in every row of a repeat block, validations and Set Errors that fire now, and custom components, with the count on the step's row, and a Valid column at the end of every row says it at a glance: ✓ passes its rules now, ✗ would stop Next, – the panel cannot tell; the step the script is on carries an accent bar on its left edge. Problems lists what is provably wrong in the definition and shows only while there are any; names that are not in the data yet are listed apart and never counted. A Properties tab explains each setting of an element; the Calls tab shows what an action sends and where the answer lands; with nothing selected the pane summarises the script. A hidden element shows a closed eye, a conditional one a small diamond; the marks sit in their own column at the right, whose header opens a legend of every mark. Follow step keeps the current step selected as the script moves on. Under Advanced: a timeline of the steps visited, Compare definition against a saved one, Export as Markdown, CSV or JSON, and Go to this step in a step's row menu, which asks the running script to show an earlier step again even when it hides its Previous button. Formulas are evaluated as estimates, marked estimated in sentences and ≈ in tables, and never counted.
  • Calls — every Apex call the page makes, with Data Mappers and Integration Procedures named by key, batched calls split apart, and a verdict that does not trust HTTP 200 (Succeeded or Failed, with "no response" and "no body" told apart), with the failure text at the top of the detail. A chainable procedure that ran as several calls is one row, chain · N calls, with each call under it, and repeated calls are tagged. Tick several calls to add up their run time (total, first to last, average, slowest, failed), exactly in milliseconds or as seconds and minutes. Filter with words or in:, url:, step: and repeat:. Open a call for its Input, Output and Options, the data changes right after it, Compare with previous or with the last success (side by side, like Compare data), Copy input, and Copy as Apex, which turns the call into anonymous Apex that re-runs it. An oversized input gets a chip with the keys that take the room; a slow call says where its time went; a repeat that sent the same input as a successful call says so. With Allow test calls on (Settings, off by default), Re-run… opens a captured call with its input to edit and send again, and New test call… composes one; the answer lands as a new row tagged test and re-run, to compare with the original; From the data… in the form picks nodes of the data JSON into the input, each under the name the procedure expects. A designer's Preview of an Integration Procedure or Data Mapper, run with the designer open in the inspected tab, is listed too and opens on a Debug tab: every step in run order with its type, status, elapsed and CPU time, its input and output, the response, and the debug log with the queries it ran; with Allow test calls on it can be re-run with other input. An Integration Procedure the page calls with isDebug: true in its options gets the same Debug tab, under its own name, with no designer needed. The list keeps the Result mark in its last column, after the time.
  • Linked together — jump from a value in Data to its element in Structure and back, from an action to its calls, and from a call to the step it ran on. Open in Designer opens the selected script in the OmniStudio Builder or the OmniScript Designer, deciding between core and a managed package from the host element, the definition, the page address and the calls seen; Settings can force either. Inspect element (under Advanced) selects the host element in the Elements tab and leaves it as $omni in the Console.
  • Mask values — a switch (off by default) that replaces strings and numbers with placeholders in everything you copy, save or export, and in the watch list and change notices on screen. It always starts off, and a chip in the status bar says when it is on.
  • Debug bundle and bundle viewer — Save a debug bundle writes everything the panel shows as one JSON file for a bug report; with Mask values on, org data is masked and only the script's names and settings stay. Open bundle… loads one back as a read-only session in every tab, and the bundle viewer on this site does the same in a plain browser tab. Copy report puts a few lines of Markdown for a ticket on the clipboard. Compare JSON, the button at the right end of the tab strip (also Ctrl/Cmd+Shift+L and the Tools row), takes two pasted JSON values, says what is wrong with text that is not JSON and can read Apex maps, single quotes and unquoted keys loosely, shows each side as Text, Tree or Form, and compares them side by side.
  • Settings — the gear before ? opens them: a Profile (Simple, Standard or Expert sets the switches at once), Text size, Mask values at start (Mask values on at every DevTools start, kept with Remember my settings on or off), the Refresh rate of the Data tab (Fast, Normal or Gentle), every setting that differs from its default with a Reset, and Restore default settings. Settings last until DevTools is closed unless you tick Remember my settings (off by default), which keeps them, the views you last chose and your watch list in the browser's extension storage on your computer, never any data. Hide the list with Ctrl+\ to give the detail the whole width.
  • Easy to step into — with Advanced off each tab is one list, one filter box and a few buttons; the deeper tools sit under Advanced, in a detail tab, behind a filter prefix or in the right-click menu. A four-step tour the first time, a searchable ? help with a Start here list per tab, right-click any control for its help entry, and the reference and guides on this site, generated from the same help. Light and dark, from 340 px up, keyboard and screen-reader friendly.

Replay, which recorded the steps you keep repeating and replayed them, is now an extension of its own: OmniScript Replay.

Install

Chrome Web Store · source on GitHub (GPL-3.0)

Privacy

Only the storage permission, for the order of the tabs, the first-run tour flag and, if you tick Remember my settings, your settings and watch list; no host access. Nothing is sent anywhere unless you turn on Allow test calls (off by default), and then only the call you compose, to the org of the current tab; the OmniScript and its data are never changed. Read the full privacy policy, or the source — it is all there is.
