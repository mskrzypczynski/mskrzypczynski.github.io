Privacy policy — OmniScript Replay

Last updated: 28 October 2026

The short version

This extension collects nothing and sends nothing anywhere. The only thing it stores in your browser is what you record: your recordings and the replay options, in the browser's extension storage on this computer, until you delete them. Everything else it holds, including the scope bar's settings, is kept in memory and is gone when DevTools closes.

It requests one permission, storage, for those recordings and options, and no access to any website. It has no background service worker, no content scripts, and makes no network requests of its own. It changes the page you are inspecting only while you replay a recording.

What it reads, and when

The extension only does anything while you have Chrome DevTools open and the OmniScript Replay panel in view, or while a recording or a replay you started is running.

Page data. It reads properties of elements on the page you are inspecting, using the standard chrome.devtools.inspectedWindow API — the same access the DevTools Console already gives you: jsonDataStr (the live data payload), jsonDef (the script's definition: its steps and elements) and, with the definition, the custom labels of scriptHeaderDef (so an Edit Block's add button is found by the text it shows in a multi-language script); a custom label the header does not resolve is read through Lightning's own $A.get on the page, which only returns the label's text. To find those elements it walks the document, any open shadow roots, and same-origin iframes.

Frames. It asks DevTools which documents are loaded, so it can find an OmniScript inside an iframe.

What it writes to the page. While scanning it sets window.__omniHosts on the inspected page to an array of the elements it found.

While recording. While recording it reads the page URL (location.href) on every check, to keep the start page, its query parameters and any page change with the recording. It adds one click listener to the page and keeps the labels of the buttons, links, tabs and menu items you click (and whether they were inside the script) in window.__omniReplayOpen, so a replay can press the same buttons outside the script and open a script that lives in a flyout or modal; the listener and the variable are removed when you press Stop. Recording reads the script's data property after each step. It also adds listeners for keystrokes and clicks to the script while Record is on, inside its components' shadow trees too, so a button pressed in a custom component or an Edit Block is recorded with its label. While recording the page holds: window.__omniReplayShadows (the shadow trees listened to), window.__omniReplayRoots (the scripts listened to), window.__omniReplayPressScope (the element names it files presses and clicks under), window.__omniReplayScanAt (when it may next look for new shadow trees, after a slow look), window.__omniReplayLastPoll (when the panel last checked; the listeners remove themselves and these variables about 15 seconds after the panel stops checking, for example when DevTools is closed while recording), window.__omniReplaySnap (custom components' controls: their labels and values; also those of Blocks drawn by an LWC override, and the row form of an Edit Block drawn by one, taken when you press a button in it such as Save), window.__omniReplayClicks (the action buttons you press), window.__omniReplayPresses (the labels of the other buttons you press in the script), window.__omniReplayTouches (the names of the fields you change, in order, not their values; the values come from the script's data), the marker properties __omniReplayWatch (on the script) and __omniReplayPress (on a shadow root), and __omniReplayPressed on the click event itself. It reads them back into the panel. When you press Stop, the listeners, the marker properties and all of these variables are removed. Password fields are never recorded.

While replaying. Only when you press Replay, and only until the replay ends or you press Stop, does the extension change the page: when Reload page first is on (the default) it reloads it, or opens the page the recording started on (or the recorded page of a later script) with its URL parameters; it clicks the recorded buttons that open the script; types the recorded values into the script's fields and clicks its options (when Add missing options is on, it adds a value a dropdown does not list as an option); presses the action buttons and the other buttons you pressed while recording (in custom components, and on the page outside the script unless Click buttons outside the script is off), its Next and Previous buttons (also Next on a step the recording does not have), the custom component buttons that took the script back, and the buttons that changed the page, opening a recorded page by its address when its button is not there. With Outline what it clicks on (the default) it keeps the elements it just touched in window.__omniReplayMark and draws a short-lived outline over each (div.__omni_replay_outline, removed after a second and a half). It writes nothing else to the page and changes no OmniScript data at any other time. While it types a field key by key it counts the fields still being typed in window.__omniReplayTyping, and Stop sets window.__omniReplayStopped so the typing ends at the next key. When the replay ends or is stopped, window.__omniReplayTyping, window.__omniReplayStopped, window.__omniReplayMark and any outline still showing are removed; if a field is still being typed at that moment, window.__omniReplayEnded is set and the last typing removes all three itself. Each press and fill is numbered in window.__omniReplaySeq, which stays on the page after the replay, so a call that arrives late from an earlier moment never presses anything. A text check (a check that a text is shown or not shown) only reads the visible text of the script's current step and answers found or not found; nothing of the page's text leaves it.

All of this stays in the DevTools panel in your browser. It is never transmitted.

What is stored in your browser

Only your recordings and the replay options. A recording holds its name, its place in the list, the OmniScript's Type/SubType/Language, the steps passed in the order you went (the same step again after going back), the values in them (as read from the script's data, or from a custom component's controls), the names of the action buttons pressed, the moves back with the label of the button that made them, the switches to another script with that page's URL, the page changes with the label of the button that made them, the other buttons pressed in each step with their labels and, so a replay in another language can find them, their name, id and data-* attributes, icon and position, the labels of the buttons clicked to open the script, and the page URL it started on with its query parameters, and the checks you add to it with the values and texts they expect. The options are Reload page first, Pause before each Next, Outline what it clicks, Add missing options, Click buttons outside the script, Accept the script in any language, the Languages list you build (each language's name, code, date format and number style, which ones to run and which one to use for dates and numbers), the language URL parameter name, the waits under Timing, Stop when a check fails and Wait for a check. They are kept with chrome.storage.local, the browser's extension storage, on this computer only; they are not synced. They stay until you delete a recording in the panel or remove the extension. A recording can hold whatever you typed into the script, so record with test data.

The extension does not use localStorage, sessionStorage, IndexedDB or cookies. The scope bar's settings (Mask values, Advanced, Frame and Child scripts) and the last result of each recording are held in memory and last until DevTools is closed. The Restore default settings button in the help panel puts them back without reloading DevTools.

What leaves your machine

Nothing, unless you ask for it.

Export writes tests (recordings with their checks) to your own disk when you press it (with Mask values on, a recording's values, expected values and URL parameters are masked and its URL cut to its path). Import reads only the files you choose or drop on the panel, and shows what it would change before anything is saved. Save report writes a run report (HTML, text or JSON) to your disk and Copy report puts it on your clipboard, masked when Mask values is on; copying from the test data tree puts what you chose on your clipboard. Nothing is uploaded.

The toolbar popup and the help panel contain a link to buycoffee.to, which opens in a new tab only if you click it. That site is operated by someone else and has its own privacy policy. No information about you is passed to it by this extension.

Analytics and third parties

There are none. No analytics, no telemetry, no crash reporting, no advertising, no cookies, no user accounts, no third-party services of any kind. No data is sold or shared, because none is collected.

Your test data is your responsibility

A replay types into the script you point it at, as you would. Use it on a scratch org or a sandbox with test data, not on production records. A recording holds whatever you typed into the script; it stays on your computer, but an exported recording is an ordinary file, and where it goes next is your decision. Turn on Mask values before sharing one, and follow your organisation's policies and any applicable data protection law such as the GDPR.
